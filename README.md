# Document Intake AI

FastAPI-монолит принимает PDF, DOC/DOCX, TXT, JPG/PNG и многостраничный TIFF.
Shared-VLM самостоятельно определяет регистрационные документы и приложения по
изображениям. После фиксации состава Docling извлекает OCR/таблицы, VLM классифицирует
документы и извлекает реквизиты.
Результат — JSON **1.0** и отдельный PDF-комплект для каждой регистрации.
1С получает файлы через REST без открытия web. Запись и поиск в 1С сервис не выполняет.

Текущая приёмка: реальные OCR/VLM проверены, но распознавание писем ещё имеет
ошибки реквизитов и классификации. [Результаты и ограничения](reports/validation.md).

По умолчанию анализ идёт автоматически. Можно получить предложение VLM для проверки
или пропустить определение границ: каждый исходный файл станет одним документом.
Горизонтальная лента позволяет вручную менять диапазоны ещё до OCR/VLM; сохранённый
состав подтверждается перед извлечением. Ctrl/Cmd выбирает несмежные листы, «Создать
диапазон» объединяет только выбранные страницы. Если VLM не вернула корректный план
или исчерпан бюджет разделения, предлагается черновик по одному листу с обязательной
проверкой и подтверждением; готового JSON до этого нет.
Данные доступны **1 час после завершения**; ожидание ручного решения ограничено часом
после подготовки всех превью. Источник и PDF-комплект: до 400 МиБ/1000 страниц;
пакет: до 1024 МиБ/2000 страниц/20 файлов. Пределы настраиваются независимо.

Структура: `app/domain` — контракты и каталог; `application` — сценарии/порты;
`infrastructure` — PostgreSQL, RabbitMQ, Docling, VLM, PDF; `presentation/http` — REST;
`web` — Jinja2/CSS/JS; `prompts` — две базовые версии; `migrations`, `tests`, `reports`.

Для развёртывания нужны Linux, Docker с Compose v2, доступ к Docker daemon,
существующая сеть `ai-shared`, работающие shared RabbitMQ/Docling/VLM и разрешённый
`DOCLING_API_KEY`. Сервис не создаёт и не перезапускает shared-компоненты.

```bash
bash scripts/up.sh
```

Первый запуск атомарно создаёт отсутствующий `.env` с собственными случайными
`DATABASE_PASSWORD`, `RABBITMQ_PASSWORD`, `SESSION_SECRET`, `DOWNLOAD_SECRET`,
`API_KEYS` (`onec`, `telegram`, `evaluation`). Можно заранее создать `.env` только
с разрешённым `DOCLING_API_KEY`: скрипт добавит недостающие собственные секреты,
сохранит заданные значения и ограничит права собственного файла до `0600`.
Значения не печатаются; невалидные заданные секреты требуют исправления владельцем.
Во время `up.sh` не редактируйте `.env`: конфликт остановит запуск, не удаляя ваши байты.
Если ключ Docling ещё не предоставлен через `.env` или окружение, добавьте его
в созданный файл и повторите ту же команду.
Не копируйте весь `.env.example` и не используйте секреты соседних проектов.

Pydantic Settings: `.env.example` → `.env` → environment процесса.
Каталог несекретных параметров находится в `.env.example`.
OCR по умолчанию использует проверенные `tesseract` и языки `iso:ru`, `iso:en`.
VLM получает `VLM_ENABLE_THINKING=false` для прямого JSON в пределах timeout.
По умолчанию UI: `http://192.168.55.3:8084/`, Swagger: `/docs`.
Порт `8083` не используется. Firewall должен разрешать `8084` только нужной LAN/VPN;
скрипт firewall не меняет. Web без логина, с изолированной HttpOnly-сессией и CSRF.

Проверки с видимым выводом:

```powershell
.\ops\check-quality.ps1
```

```bash
bash scripts/test.sh
# После развёртывания, с локальными examples и evaluation key:
bash scripts/test.sh --live
```

Chromium автоматически устанавливается при `./ops/check-quality.ps1 -Browser`
или `bash scripts/test.sh --browser`.
На Linux нужны системные библиотеки Playwright. Реальная модель и браузер — разные проверки.
Если Windows запрещает выполнение `.ps1`, разовый запуск без изменения политики системы:
`powershell -NoProfile -ExecutionPolicy Bypass -File .\ops\check-quality.ps1`.
