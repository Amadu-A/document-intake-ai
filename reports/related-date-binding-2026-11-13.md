# Привязка связанных судебных дат — 13.11.2026

Основа проекта: `main`, `d8a73649ad11317df293118dddda2b984b0a45e1`.
Актуальные shared docs: `839d419432fc25bc988e5871f7e53f6d282a2e77`.
Перед исправлением локальное дерево было чистым, локальный, GitHub и серверный HEAD
совпадали. На сервере выполнялись только диагностика и обращения к сервисам;
код, конфигурация и контейнеры не изменялись. Агент не выполнял commit/push.

## Ошибка владельца и причина

В приложенном логе `scripts/up.sh` завершился успешно: readiness, реальный AMQP
consumer, OCR/vision и внешнее скачивание с checksum прошли. Linux `--live`:
**1 failed, 320 passed, 3 skipped**. Ошибка —
`test_real_court_correspondence_and_downloads[organization]`.

Частный серверный отчёт: с организацией **112/113**, без неё **117/117**.
Единственное расхождение — `court_cases[0].date` у группы физических страниц [2,3,4].
Модель записала дату вступления судебного акта в силу вместо даты самого акта.
Обе даты напечатаны в источнике; противоречивая хронология источника не даёт права
подменять их. Серверный отчёт, PDF и эталоны сверены; исходные даты не публикуются.

## Исправление

- Для связанных судебных реквизитов одновоконной группы VLM независимо перечитывает
  даты по изображениям. Передаются номера/типы, без старых дат, summary и OCR.
- Приватное свидетельство содержит роль даты, буквальное написание, цитату с номером
  и физическую страницу. Проверяются индексы, принадлежность страницы, номер в
  цитате, нормализация буквальной даты и соответствие роли виду ссылки.
- Вступление в силу, заседание, выдача копии и дата текущего документа не заменяют
  собственную дату связанного акта/дела/производства. Семантику определяет VLM;
  backend проверяет ответ, не выбирает дату из OCR и не исправляет хронологию.
- Ссылки обрабатываются порциями по 12 без ограничения общей длины. Неизвестная
  дата остаётся null с предупреждением. Некорректный ответ использует существующие
  ограниченные повторы; превышение бюджета не объявляется успешным распознаванием.
- При изменении даты VLM уточняет только summary; остальные реквизиты сохраняются.
  Проекция `one_c.comment` формируется после проверки дат и summary.
- Новый базовый prompt — `extraction-v4`; старые версии и snapshots сохранены.
  Разделение остаётся v3. Live-диагностика выводит только страницы и пути расхождений,
  а значения остаются в игнорируемом частном отчёте.

Схема JSON 1.0, справочник, границы, рендеры, Compose, Settings, secrets, TTL,
скрипты запуска и утверждённые эталоны не изменялись.

роли, чужие страницы/номера, буквальная дата, потерянные/повторные индексы, null/warnings,
неизменность исходного ответа, отсутствие OCR/старых дат в контексте, порции 12/12/1

v4, сохранить и загрузить судебный PDF заново. Ожидать четыре комплекта [1,8],

сверить собственную дату судебного акта с источником: дата вступления в силу не
