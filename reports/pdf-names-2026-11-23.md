# Полные имена разрезанных PDF

Основа: main / 7d3858e490ce481a2e130e738deedee0dac57704, remote main сверён.
Правила shared: LLM_CONTEXT f42ede5, ENGINEERING_GUIDELINES 5e6a9c1.
Commit/push, изменения серверного кода и shared-ресурсов агент не выполнял.

## Изменения

Существующий app/domain/document_names.py формирует одно имя:
`Полное название № номер от ДД.ММ.ГГГГ.pdf`. Префикс doc_N_ отменён. Папки ZIP doc_N
сохранены; download, status, JSON 1.0/2.0 и basename ZIP используют одинаковое оформление.
Нумерация конфликтов (2), (3) выполняется в глобальном порядке пачки, включая совпадения
после очистки, Unicode-замен и различия регистра Windows. Совпадение с уже имеющимся
именем, содержащим (2), не вызывает перезаписи.

Используются только classification.document_kind и достоверные собственные номер/дата.
При отсутствии вида сохранён прежний fallback направления письма/«Документ».
Заголовок, связанные документы и дата обработки не используются вместо реквизитов.
Помеченные low_confidence_fields номер/дата в имя не включаются; исходные JSON-факты
при этом не изменяются. Дата форматируется явно с четырьмя цифрами года на Windows/Linux.

Названия не обрезаются прежними лимитами 48/32 символа, пробелы не заменяются подчёркиваниями.
Нормализуется регистр обычных слов; официальные аббревиатуры, написание собственных имён
и названия в кавычках сохраняются. Запрещённые знаки названия очищаются с сохранением
границ слов. В официальном номере используются полноширинные аналоги запрещённых знаков:
`/` → `／`, `\` → `＼`, `:` → `：` и аналогично для остальных. В JSON номер остаётся исходным.
Управляющие символы не допускаются в имени, Windows device names защищены.

Невозможное полное имя свыше 255 UTF-8 байт диагностируется кодом
`409 document_name_too_long`; реквизиты и название не сокращаются молча.
Все перечисленные в ТЗ имена помещаются в лимит и проверены побайтно.

В app/application/exports.py добавлена проекция актуальных имён для уже готовых заданий
со старыми metadata. Повторный OCR/VLM и миграция не нужны. PDF bytes, страницы, SHA-256,
TTL, классификация и схема JSON не меняются. Новые имена входят в существующий fingerprint
ZIP; старый архив с другими именами не переиспользуется. Исходники не переименовываются.

Изменены два production-модуля; обновлены README, AGENTS, API/architecture/operations/
integration-workflow и только значения file_name в учебных JSON docs/samples.
Добавлен tests/test_document_names.py; актуализированы прежние проверки archive/v2/browser.
Распознавание, промпты, схема JSON 1.0/2.0 и приватные examples не менялись.

## Проверки

Новые регрессии покрывают все имена ТЗ, длинный вид и номер, слеши/остальные запрещённые
знаки, отсутствие и сомнительность реквизитов, точный формат даты, CAPS LOCK,
официальные аббревиатуры и имена собственные, коллизии после Unicode-замены,
последовательные дубликаты, сохранность исходных фактов и физический лимит ФС.
REST/SQLite/storage проверка сверяет status, JSON 1.0/2.0, Content-Disposition и ZIP
на старых metadata, а также неизменность фактов и совпадение PDF bytes.
Прежние тесты продолжают проверять owner/capability/TTL, порядок страниц и checksums.

Пропуски относятся к opt-in live/browser/private/platform, не объявляются live-проверками.

В UI скачать отдельный PDF и ZIP одного задания: basename должен совпасть, внутри
архива остаются папки doc_1/doc_2. Проверить полное название, №, дату ДД.ММ.ГГГГ,
слеш номера как ／; в JSON должен остаться /. При двух одинаковых документах второй
получает (2). При отсутствии номера/даты нет пустых «№»/«от». Готовое задание прежней
версии должно скачиваться с новыми именами без нового запуска распознавания.
