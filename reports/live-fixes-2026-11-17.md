# Исправление проверки эталонов и судебных дат

Основа: `main`, `43f24fa`; локальный HEAD и remote совпадают. Актуальные shared
инструкции проверены. На сервере выполнялись только диагностика и обращения
к существующим сервисам; код, конфигурация и контейнеры не изменялись.
Commit/push агент не выполнял. Существующий stash сохранён.

## Причины

Приложенный `scripts/up.sh` завершился успешно: миграция, readiness, AMQP consumer,
реальные OCR/VLM и скачивание PDF прошли. Ошибки возникают позже, в `--live`.

- Старые проверки эталонов требовали отдельный последовательный JSON и отклоняли
  исторические несмежные группы. Файлы `_cut.json` сами по себе не исправляют
  распознавание. В рабочие файлы возвращено исправление из stash: приоритет
  `.adjacent.expected.json`, затем `_cut.json`, затем исходный JSON с `range`.
  Исторические группы разбиваются только на непрерывные части; разные исходные
  группы не сливаются. Источник, SHA-256 и способ получения ожидания фиксируются.
  Ожидание вычисляется до вызова модели; исходные файлы не изменяются.
  Ошибочный явный эталон остаётся ошибкой. Отсутствующий необязательный приватный
  набор обозначается NOT_RUN, но явно включённые live-проверки требуют fixtures.
- На страницах 5–6 судебного примера VLM возвращала дату и номер постановления,
  обрезая цитату до номера. Напечатанная дата находится в начале того же абзаца.
  Три одинаковых непроверенных ответа приводили к `schema_validation_failed`.
- В исходном полном судебном эталоне дата исполнительного производства осталась
  `null`. По ранее данному разрешению владельца создан частный
  `examples/суд_ув.expected.json`: изменено ровно это поле после визуальной сверки
  PDF. Исходный JSON сохранён побайтно. Новый файл исключён из Git и требует SCP.

## Исправление

VLM сначала цитирует целое предложение/абзац с номером и собственной датой,
включая дату в начале предложения; затем копирует буквальную дату и нормализует
её только в поле `date`. Повтор получает предыдущий candidate, индекс ссылки
и конкретную причину: отсутствующий номер, отсутствующая в цитате буквальная
дата либо неверная нормализация. Проверки доказательства не ослаблены.
Непроверенные значения после исчерпания попыток не публикуются.

Изменены `app/application/analysis.py`, `app/application/related_dates.py`,
`app/domain/related_dates.py`, `tests/test_related_dates.py`,
`tests/segmentation_support.py`, `tests/test_segmentation_examples.py`.
Новый tracked-файл — этот отчёт. Удалённых файлов нет. JSON 1.0, миграции,
настройки, базовые редактируемые промпты и алгоритм границ не изменялись.
Нужна пересборка собственных API/worker обычным `scripts/up.sh`.
