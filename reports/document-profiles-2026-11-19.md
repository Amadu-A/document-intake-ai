# Виды документов, расширенный результат и интеграционный API

Основа — `main` / `14532371c80206bc4bffc66e8eff623f735dac10`, оба ТЗ владельца
от 19.11.2026. Изменения подготовлены одним набором; агент не выполнял add/commit/push.
Серверный код и shared-конфигурация не менялись. SSH использовался для read-only
проверок runtime и доступа к OCR; запросы VLM выполнялись в существующий LAN endpoint.

## Реализовано

- Единый immutable реестр D01–D11; фактический вид независим от закрытого пути писем.
  Все шесть родов получают общие реквизиты. Профильные детали типизированы; неизвестный
  вид сохраняет общие факты и warning без подстановки чужого профиля.
- Классификация каждого утверждённого блока предшествует извлечению. Состав и порядок
  блоков неизменны, продолжения не превышают восьми физических страниц за запрос.
  D02 ограничен исполнительным листом; счёт D03 — payment_request. Договорные роли
  требуют доверенной организации, цитаты и физической страницы подтверждения.
- JSON 1.0 имеет прежнюю схему. Новый `/api/v1/jobs/{id}/extractions` отдаёт отдельный
  JSON 2.0: все source_pages, классификация, серверные metadata категории, общие поля,
  details, evidence, one_c, recognition, warnings и PDF. Деньги v2 — точные десятичные строки.
  Старые v1-only задания возвращают 409 extractions_unavailable, а не выдуманный v2.
- Evidence проверяется на путь, статус, источник и страницы утверждённого блока.
  Собственные номер/дата требуют image основной части, вид — обосновывающую цитату.
  Неполнота карты вторичных полей отмечается warning. Confidence не генерируется.
  Независимые визуальные проверки основной даты и назначения судебных дат сохранены.
  VLM-схема явно требует core evidence и допускает только закрытые альтернативы писем.
- Прежняя заглушка неписем не создаётся. Исторический unsupported_template читается
  для совместимости старых заданий. Ошибки отдельных блоков сохраняют PDF и диагностику.
  Контрагент one_c — отправитель входящего либо адресат исходящего; при неизвестном
  направлении null. Поиск, GUID и регистрация в 1С отсутствуют.
- Headless API: загрузка, старт, режимы, просмотр, серверные действия редактора,
  полный PUT/undo, подтверждение, отмена, история, JSON 1/2, источники, PDF, ZIP, SSE,
  промпты. UI вызывает те же сценарии. Revision/owner/lock/fence/TTL сохранены.
- Swagger содержит типизированные реальные модели, multipart upload, X-API-Key,
  примеры тел, ошибки и binary/SSE ответы. Публичные OpenAPI и JSON Schema выгружены
  в docs; Swagger работает с локальными ресурсами. ReDoc намеренно отключён.
- Ожидание подтверждения и terminal retention — по 24 часа; budgets worker/HTTP прежние.
  Сессия 3 дня с продлением активности покрывает полный цикл. Обновление старой cookie
  сохраняет owner. «Мои задания» восстанавливает свою обработку в том же браузере,
  даже если sessionStorage новой вкладки пуст. Закрытая вкладка не отменяет worker.
- Увеличенная зона загрузки, краткая подпись организации, статус с точкой и текстом,
  фактические счётчики, правильное отображение manual_override. В реквизитах доступны
  категория, детали и переход к странице evidence. Три колонки, лента, перенос и поворот сохранены.
- ZIP: doc_N/фактический_вид[_номер][_дата].pdf, настоящее время UTC вместо 1980,
  обновлённый fingerprint кеша, безопасные Unicode/Windows имена. Отдельные PDF сохраняют
  прежний doc_N_ префикс. Подписанные ссылки действуют до пяти минут в пределах TTL задания.
- Исправлена выявленная полной браузерной регрессией гонка: snapshot/SSE не стирает
  сообщение о неудачной отмене; новый пакет и успешное завершение сбрасывают его.

## Реальные примеры и ограничения точности

Проверены неизменность исходных PDF/JSON и отсутствие diff в examples/.
Для пяти файлов свежая vision-классификация/экстракция использовала проверенный прежний
локальный Docling-кеш; это не замер холодного OCR. Границы для проверки извлечения
задавались явно одним операторским блоком на исходный файл; их нельзя считать доказательством
автоматического разделения. Технические отказы первых итераций зарегистрированы отдельно.

Один файл дополнительно прошёл полный новый локальный REST → свежий Docling → VLM →
JSON 1.0/2.0 → ZIP: 52 проверки матрицы совпали, 200 на v2/ZIP. Публикация AMQP в этом
локальном прогоне заменена прямой доставкой production process; RabbitMQ нового кода
на сервере не разворачивался. Сам worker, repository, адаптеры, REST и PDF были настоящими.

Её значения, документы, OCR и подписанные URLs не включаются в коммит.

Прежняя публичная матрица ожидала пустые поля заглушек неписем. В версии 1.2 соответствующие

Новые snapshots используют extraction-v6/segmentation-v5, пользовательские overrides сохраняются.

После пользовательского commit/push на сервере:

```bash
cd ~/projects/document-intake-ai
git pull --ff-only
sed -i -E '/^(RETENTION_SECONDS|CONFIRMATION_TIMEOUT_SECONDS|SESSION_TTL_SECONDS)=/d' .env
bash scripts/test.sh
bash scripts/up.sh
```

sed удаляет только старые несекретные overrides трёх TTL; реальные секреты сохраняются.
Новые .env-переменные не нужны. Каталог .env.example → собственный .env → process environment
по-прежнему читает Pydantic; переменные процесса имеют приоритет и также требуют проверки.
Новые таблицы не нужны, старые calculated deadlines не продлеваются задним числом.
После обновления старую открытую web-вкладку следует перезагрузить для нового CSRF/cookie.

Вручную: загрузить письмо и неписьмо; увидеть род/фактический вид/категорию и реквизиты;
перейти по evidence к нужному источнику; переместить лист, утвердить и сверить PDF/ZIP;
закрыть вкладку во время обработки и восстановить через «Мои задания» в том же браузере;
проверить предупреждения неопределённых границ большого файла. В /docs выполнить
upload → review/edit → confirm → result/extractions → PDF/ZIP с собственным API-ключом.

См. [полный HTTP workflow](../docs/integration-workflow.md), [OpenAPI](../docs/openapi.json).
Multipart оформлен стандартными File/UploadFile средствами
[FastAPI](https://fastapi.tiangolo.com/tutorial/request-files/); фактическая файловая форма
дополнительно проверена Chromium. Серверный rollout и LAN smoke нового релиза выполняет владелец.
