## Ошибка и диагностика

PostgreSQL, consumer, OCR/vision и HTTP/PDF checksum — PASS. Linux `--live`:
**1 failed, 353 passed, 3 skipped**. Упал только судебный пример без организации.

Частный отчёт без контекста: status=failed, error_code=model_output_limit, 637,71 с.
С организацией — completed_with_warnings, 113/113 проверок, 183,04 с.
Сервер использовал 16000 max_tokens, timeout 180 с, три model attempts.
Технические счётчики SSE показывают три неудачных повтора проверки связанных дат;
в двух последних фрагментах около 15,9 тыс. символов и по 5206 переводов строк.
Это признак зацикливания форматирования. Частный текст и реквизиты в отчёт не включены.

Фактический shared-VLM: healthy, image `vllm/vllm-openai:v0.29.0`.
Запросный disable_any_whitespace в синтетической пробе не изменил pretty JSON;
флаг без JSON-ограничения вместе с response_format отвергнут HTTP 400.
В этой версии xgrammar использует настройку whitespace из общей конфигурации:
[официальный исходный код](https://github.com/vllm-project/vllm/blob/v0.29.0/vllm/v1/structured_output/backend_xgrammar.py).
Shared-конфигурация не менялась; приложение сохраняет прежний response_format/json_schema.

## Исправление

- Новый JSONWhitespaceGuard прерывает поток после более чем 512 подряд идущих
  JSON-пробелов вне строковых значений. Состояние кавычек/escape сохраняется между
  delta. Строковые пробелы, кавычки, переносы и реквизиты не переписываются.
- HTTP stream закрывается; частичный ответ не становится результатом. Используется
  прежний model_output_limit и прежний ограниченный application retry.
- Только повтор после model_output_limit получает техническую инструкцию компактного
  JSON. Первые обычные запросы сохраняют прежние инструкции. Общая инструкция для
  всех запросов была проверена промежуточно, ухудшила реальные результаты и не вошла
  в итоговое решение; промежуточные неудачные матрицы сохранены отдельно.
- Прогон также выявил ошибки технических адресов/индексов RelatedDatesReading.
  Схема конкретной порции теперь задаёт точное число записей, допустимые индексы и
  существующие пары file_id/page_number. Эти поля выбирает VLM из входных адресов;
  backend не исправляет их после ответа. Даты, роли, цитаты и предупреждения по-прежнему
  определяет VLM; nullable поля и базовая DTO-схема сохранены.
- Model-retry metadata дополнены schema/task, без документа/ответа. Неудачный live-тест
  печатает status, error_code, fallback_code и время, а не только путь отчёта.

Ни токеновый лимит, ни timeout, retries, image budget, схема JSON 1.0, справочник,
промпты v3/v4, настройки/секреты, TTL, инфраструктура, скрипты и эталоны не менялись.
