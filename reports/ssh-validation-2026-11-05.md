## Подтверждённые причины из лога

1. Заранее созданный через редактор sparse `.env` имел широкие права и не содержал
   собственных секретов. Bootstrap теперь ограничивает права своего regular file
   и добавляет только отсутствующие секреты. Непустые значения не заменяются.
   Новый файл создаётся атомарно; существующий дополняется через `O_APPEND`.
   При обнаруженной параллельной записи запуск прекращается без удаления байтов.
2. Установленный Docling Serve 1.38.2 не принимает старый `ocr_engine=tesseract_cli`:
   HTTP 422. Рабочий контракт: `ocr_preset=tesseract`,
   `ocr_lang=iso:ru,iso:en`, `target_type=inbody`. Пресеты/языки находятся в Settings,
   `.env.example` и Compose, а не в локальных секретах.
3. HTTP 404 нового запроса означал отсутствие результата задания. Технический лог
   OCR показал несовместимые идентификаторы `ru/en` и недоступные fallback-модели.
   С `iso:ru/iso:en` растровая проба и все десять страниц примеров распознаны.
   Диагностика 422 сохраняет только разрешённые пути/типы ошибок; известный 404
   получает код `docling_task_result_unavailable` без тела документа.
4. Shared-VLM по умолчанию тратил бюджет на длительное reasoning; извлечение
   превышало 180 секунд. Приложение явно передаёт `VLM_ENABLE_THINKING=false`.
   Общий сервер, модель, alias и GPU-настройки не менялись.
5. Compose запускал дополнительный init поверх image Tini. Удалён `init: true`;
   image entrypoint сохранён. Это отдельное предупреждение, не причина HTTP 422.
6. `--live` запускался после неуспешного `up.sh`, когда API отсутствовал.
   Live-тесты требуют успешного штатного развёртывания.

Исторический `TypeError` не имел traceback, поэтому его точную причину подтвердить
нельзя. Неожиданные operations errors теперь показывают тип и координаты кадров,
не раскрывая текст исключения, аргументы или значения переменных.

## Проверка приложения

Локальный REST/ASGI, production use-cases/repository на SQLite и реальные
Docling/VLM через временные SSH-forward. Доставка в worker выполнялась локально;
серверные PostgreSQL, AMQP consumer и LAN HTTP этим прогоном не проверялись.
Две настоящие synthetic-пробы OCR скана и VLM vision/JSON прошли.

Полный прогон пяти PDF завершился проверенным JSON с предупреждениями для каждого
файла. Прошли **238 из 238 структурных/download-проверок**: регистрационные единицы,
полнота и порядок страниц, приложения, оригиналы и комплекты PDF, manifest,
анонимные подписанные скачивания через REST, byte_size и SHA-256.

Затем контекст OCR сокращён без потери текста, таблиц и геометрии; полный ответ
Docling сохраняется отдельно. Ранее метаданные занимали до 66 тысяч символов
на страницу и приводили к обрезанию полезной информации. На тех же настоящих OCR
и изображениях повторены VLM-извлечение со штатными retries и план претензии.
