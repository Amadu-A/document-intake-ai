# Перетаскивание листов и архив документов

Последующее уточнение формата ZIP: [папки doc_N](archive-folders-2026-11-18.md).
Описанная ниже плоская структура относится к первоначальной проверке этой доработки.

## Изменения

Миниатюры можно захватывать мышью и отпускать перед/после другой страницы.
Маркер показывает место вставки, у края лента прокручивается, Shift/Ctrl/Cmd
сохраняют множественный выбор. Переносимые страницы входят в целевой диапазон.
Pointer-жест переживает виртуализацию карточек; Escape, pointercancel и потеря
фокуса отменяют его. Ручки ↔ сохраняют прежнее назначение — изменение границ.

Каждый завершённый перенос использует существующий PUT полного плана с
`page_order` и `expected_revision`. Confirm фиксирует именно сохранённую ревизию.
Порядок не ограничивается DOM: он попадает в ApprovedPlan, JSON pages и PDF.
После lock/TTL перенос недоступен. Исходные физические номера/файлы не меняются.

«Разрезать и скачать» рядом с подтверждением утверждает состав, ждёт обычного
конвейера классификации/реквизитов и скачивает один ZIP всех готовых PDF.
При уже утверждённом составе повторного confirm нет. После завершения архив
можно скачать повторно. Reload сохраняет намерение скачать текущий пакет;
«Новый пакет» отзывает старый запрос. Ошибки ZIP видны постоянно возле кнопки
и разрешают повтор без новой VLM-обработки.

Имена PDF: `doc_<segment_index>_<вид>[_<номер>][_<дата ISO>].pdf`.
Для писем — «Входящее письмо»/«Исходящее письмо»; без направления — «Письмо».
Для неписем — проверенный вид, без классификации — «Документ». Отсутствующие
номер/дата пропускаются. Связанные реквизиты не подставляются вместо собственных.
Недопустимые знаки путей/Windows нормализуются, управляющие символы удаляются,
компоненты ограничены по длине. Неписьма сохраняют действующую заглушку реквизитов.

Новые REST endpoints POST/GET `/api/v1/jobs/{id}/archive` используют те же
application-сценарии, owner/capability/CSRF/TTL, что web. До завершения — 409.
Публичный JSON 1.0 сохраняет прежние поля; имена новых PDF совпадают в JSON,
отдельных скачиваниях и ZIP. ZIP упорядочен глобально по номеру блока, включая
комплекты из разных исходников. Он собирается порциями на диске, с проверкой
размера/SHA каждого PDF, резерва диска и TTL, затем атомарно публикуется.
Отмена дожидается закрытия файлов, неполный архив недоступен. Кеш/архив живёт
в каталоге задания и удаляется общей очисткой; повтор не вызывает OCR/VLM.

## Команды владельцу

Windows:

```powershell
.\ops\check-quality.ps1 -Browser
git diff --check
git diff --stat
git add -- AGENTS.md README.md app docs tests reports/drag-archive-2026-11-18.md
git commit -m "Add page drag and named document archive"

```

Linux после push:

```bash
cd ~/projects/document-intake-ai
git status --short
git pull --ff-only
bash scripts/test.sh
bash scripts/up.sh
curl --fail http://127.0.0.1:8084/health/ready
```

`up.sh` пересобирает собственные API/worker и выполняет штатные реальные smoke
зависимостей; shared stack/credentials менять не требуется.

Вручную после Ctrl+F5 на `http://192.168.55.3:8084/`:

1. Дождаться превью/предложения, перетащить лист 31 за 32, затем далеко через
   автопрокрутку. Проверить линию вставки, исходные номера и назначение диапазона.
2. Выделить Ctrl/Cmd два несмежных листа, перетащить вместе; проверить Escape,
   undo/reload и прежнюю работу ручек ↔/кнопок переноса.
3. Нажать «Разрезать и скачать». Во время обработки перенос заблокирован;
   после неё скачивается ZIP, внутри по PDF на блок, включая его приложения.
   Проверить число файлов, имена, порядок страниц; отсутствующих дат/номеров
   в именах нет, оригинал сохраняет прежнюю последовательность.
4. Повторно скачать архив, проверить отдельный PDF/JSON и повороты просмотра.
   При новом пакете старое отложенное скачивание не должно запускаться.
