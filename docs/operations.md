# Развёртывание и проверки

Prerequisites: Linux с Docker daemon/Compose v2, coreutils `timeout`, `flock`, `ss`;
в существующей `ai-shared` работают RabbitMQ, Docling и shared-VLM.
VLM: `http://shared-vlm:8000/v1`, alias `shared-vlm`, без API key.
Docling: `http://docling-eval:5001`, разрешённый `DOCLING_API_KEY` обязателен.
Ключ предоставляет владелец общей инфраструктуры; проект не читает чужие `.env`.
Хост должен разрешать приложению syscall seccomp и иметь доступ к закреплённым images/PyPI.

```bash
bash scripts/up.sh
```

Скрипт проверяет daemon/Compose/сеть, собирает один образ API/worker, создаёт только
отсутствующий собственный `.env` (атомарно, 0600, случайные независимые secrets).
При существующем файле сохраняет его байты. Если конфигурация неполна, останавливается.
Первый запуск без внешнего Docling key намеренно останавливается до RabbitMQ bootstrap;
добавьте только выданный ключ в созданный `.env` и повторите команду.
Рекомендуемый режим секретного файла: `chmod 600 .env`.

Далее проверяет `APP_PORT`, существующий RabbitMQ-контейнер и его принадлежность `ai-shared`.
Разрешены только создание выделенного user/vhost и permissions своего vhost.
Существующий пароль проверяется без изменения; неверный пароль, служебные теги или
права user в чужом vhost останавливают процесс. Password передаётся закрытым stdin
в приватный RAM-файл, не через argv. `set -x` отключён до работы с секретами.
После bootstrap идут реальные OCR и vision/JSON пробы, своя PostgreSQL и миграции,
запуск/recreate своих API/worker, real AMQP/consumer и readiness.
Затем synthetic HTTP smoke по внешнему адресу проверяет web/API, настоящий pipeline,
JSON и скачивание с checksum клиентом без cookie/API key. Это собственный тестовый
документ, автоматически удаляемый по обычному TTL.

При повторе после `git pull` образ пересобирается, Compose пересоздаёт изменившиеся
собственные компоненты. Shared stack, чужие namespaces и volumes не удаляются.
Изменения `.env` процесса влияют на все команды с тем же приоритетом, что Pydantic.
При изменении настроек очереди уже существующая очередь может отклонить несовместимые
arguments; скрипт не удаляет её и не заменяет молча. Согласуйте миграцию очереди отдельно.

Обновление с сохранением видимых логов:

```bash
git status --short
git pull --ff-only
bash scripts/test.sh
bash scripts/up.sh
bash scripts/test.sh --live
docker compose --env-file .env.example --env-file .env ps
```

Offline tests требуют `uv` и Python 3.12–3.14. `up.sh` не требует uv/Python хоста:
использует собственный образ. `--live` требует поднятый сервис, evaluation key в
собственном Settings и пять локальных `examples`. Если что-то отсутствует, это FAIL,
а не успешный skip. Частные сравнения/замеры сохраняются в игнорируемый `reports/local/`.

Browser prerequisites: доступ к download Playwright и системные библиотеки Chromium.
Скрипт автоматически ставит закреплённый Chromium при флаге browser.
Запуск: `bash scripts/test.sh --browser`, Windows —
`.\ops\check-quality.ps1 -Browser`. Browser-тесты используют настоящие HTTP/Chromium,
но synthetic OCR/VLM; это не подтверждение качества реальной модели.
Если Execution Policy блокирует локальный `.ps1`, используйте разовую команду
`powershell -NoProfile -ExecutionPolicy Bypass -File .\ops\check-quality.ps1 -Browser`.
Она не меняет постоянные политики Windows.

Ручная приёмка из другой разрешённой LAN/VPN-машины:

1. Открыть `http://192.168.55.3:8084/` без экрана входа; `/docs` загружает локальный Swagger.
2. Проверить две вкладки промптов, отдельные тексты, восстановление только активной,
   сохранение сессии и сохранность другой вкладки после обновления страницы.
3. Загрузить `4-2591.pdf`, запустить анализ. Ожидать 1 регистрацию, страницы 1–6,
   четыре приложения и warning о расхождении дат. Подтверждать границы не требуется.
4. Проверить листание, миниатюры, масштаб; обновление SSE не меняет выбранную страницу.
5. JSON до завершения помечен как поток. После проверки — schema_version 1.0,
   экспорт доступен, PDF-комплект содержит 6 страниц, исходник скачивается отдельно.
6. Пачка с двумя независимыми письмами даёт две регистрации/PDF. Несколько источников
   сохраняют file_id/page_number в manifest; TIFF сохраняет порядок кадров.
7. Ошибка/отмена показывают диагностический статус и исходники; экспорт неподтверждённого
   JSON недоступен. После TTL ранее выданные ссылки запрещены.
8. Повторить `up.sh`: текущие credentials сохраняются, чужие RabbitMQ users/vhosts не меняются.

`/health/ready` не доказывает firewall-доступ из другой машины. Firewall ограничивает
только собственный web/API порт разрешённой LAN/VPN; private PostgreSQL не публикуется.
При будущем Internet-доступе отдельно согласуются HTTPS и `COOKIE_SECURE=true`.
Откат: вернуть согласованную версию кода владельцем и повторить `up.sh`, сохранив `.env`
и named volumes. Автоматический destructive downgrade БД не выполняется.
