# Развёртывание и проверки

Prerequisites: Linux с Docker daemon/Compose v2, coreutils `timeout`, `flock`, `ss`;
в существующей `ai-shared` работают RabbitMQ, Docling и shared-VLM.
VLM: `http://shared-vlm:8000/v1`, alias `shared-vlm`, без API key.
Текущий shared runtime по умолчанию выполняет длительный reasoning перед JSON.
Приложение явно передаёт `chat_template_kwargs.enable_thinking` из Settings:
`VLM_ENABLE_THINKING=false` по умолчанию запрашивает прямой ответ.
При включении `true` подбирайте `VLM_TIMEOUT_SECONDS` и `VLM_MAX_TOKENS` по замерам
полного ответа с учётом общего `JOB_TIMEOUT_SECONDS`; лимиты автоматически не повышаются.
Docling: `http://docling-eval:5001`, разрешённый `DOCLING_API_KEY` обязателен.
Ключ предоставляет владелец общей инфраструктуры; проект не читает чужие `.env`.
Для проверенного Docling Serve 1.38.2 каталог задаёт `DOCLING_OCR_PRESET=tesseract`
и `DOCLING_OCR_LANGUAGES=["iso:ru","iso:en"]`. При необходимости меняйте список
языков JSON-массивом доступных runtime идентификаторов; `ru`/`en` не эквивалентны
этим идентификаторам языков. Несекретные defaults остаются в `.env.example`.
Хост должен разрешать приложению syscall seccomp и иметь доступ к закреплённым images/PyPI.

Реальные проверки и оставшиеся ошибки распознавания:
[отчёт от 05.11.2026](../reports/ssh-validation-2026-11-05.md).
Readiness подтверждает зависимости и прохождение технического pipeline;
она не доказывает точность каждого извлечённого реквизита.

Для больших пачек разделение теперь выполняется VLM по готовым PNG до OCR.
`VLM_SEGMENTATION_TIMEOUT_SECONDS=900` ограничивает отдельный этап. После некорректного
ответа/исчерпания бюджета предлагается постраничный черновик с обязательным confirm.
Признак — `segmentation_source=page_fallback`; это не успешное авторазделение.
Docling нужен после фиксации состава. `DOCLING_MAX_ATTEMPTS=5`,
`DOCLING_RETRY_MAX_SECONDS=60`, `DOCLING_REQUEST_INTERVAL_SECONDS=1` ограничивают
повторы/частоту; 429 учитывает Retry-After, реальные secrets менять не требуется.
`DOCLING_ASYNC=true` использует проверенные async/poll/result endpoints существующего
Docling. `DOCLING_TASK_TIMEOUT_SECONDS=600` — отдельный бюджет ожидания конвертации,
`DOCLING_POLL_INTERVAL_SECONDS=5` — пауза polling. HTTP timeout остаётся 180 с.
Task ID хранится только в private checkpoint; restart продолжает ту же задачу.
Старый sync-контракт доступен только явным `DOCLING_ASYNC=false`; он не устраняет
продемонстрированный timeout тяжёлого 20-страничного OCR-окна. Если task/result
исчезли у shared Docling, сервис диагностирует отказ, не ставит слепо дубликат.
UI/API используют отдельные `READ_RATE_LIMIT_PER_MINUTE=600` и
`PREVIEW_RATE_LIMIT_PER_MINUTE=2400`, управляющий лимит остаётся 120/min.
Не увеличивайте их для обхода ошибки: сначала проверьте code отказа.

Базовые версии промптов: разделение v3, извлечение v3. Для существующей сессии:
«Промпты» → нужная вкладка → восстановить базовый текст → сохранить.
При обновлении извлечения с v2 на v3 восстановите вкладку извлечения; новые загрузки
получат верхний фрагмент с запасом ниже строки реквизитов. Готовые превью старого
задания не перерисовываются автоматически: для проверки исправления загрузите файл заново.
Пользовательские тексты и snapshots уже запущенных заданий сохраняются.

```bash
bash scripts/up.sh
```

Скрипт проверяет daemon/Compose/сеть, собирает один образ API/worker и атомарно создаёт
отсутствующий sparse `.env` случайными независимыми секретами.
Можно заранее записать в `.env` только разрешённый `DOCLING_API_KEY`.
Существующие непустые секреты сохраняются; отсутствующие или пустые добавляются.
Невалидные заданные секреты не заменяются: скрипт останавливается с безопасной диагностикой.
Собственный обычный файл получает права `0600` без изменения содержимого;
symlink, hardlink, устройства и файлы другого владельца отвергаются.
Системная блокировка исключает одновременный bootstrap. Существующий `.env` дополняется
одной записью `O_APPEND` и `fsync`, без replace/truncate; до и после проверяются
содержимое и inode. Это не атомарный compare-and-swap с внешним редактором.
Редактировать `.env` во время `up.sh` нельзя. Обнаруженный конфликт останавливает
запуск до настройки сервисов; пользовательские байты сохраняются без rollback.
При конфликте проверьте файл и удалите лишние дубликаты самостоятельно: повторные
непустые значения секретов bootstrap отвергает. Для обычного редактирования
дождитесь завершения `up.sh` и повторите запуск.
Первый запуск без внешнего Docling key намеренно останавливается до RabbitMQ bootstrap;
добавьте только выданный ключ в созданный `.env` и повторите команду.
Права чужого файла автоматически не меняются.

Далее проверяет `APP_PORT`, существующий RabbitMQ-контейнер и его принадлежность `ai-shared`.
Разрешены только создание выделенного user/vhost и permissions своего vhost.
Существующий пароль проверяется без изменения; неверный пароль, служебные теги или
права user в чужом vhost останавливают процесс. Password передаётся закрытым stdin
в приватный RAM-файл, не через argv. `set -x` отключён до работы с секретами.
После bootstrap идут реальные OCR и vision/JSON пробы, своя PostgreSQL и миграции,
запуск/recreate своих API/worker, real AMQP/consumer и readiness.
Образ запускает единственный Tini как PID 1; дополнительный init в Compose не нужен.
Для неожиданных ошибок operations выводит тип и координаты кадров без текста
исключения, исходных строк, аргументов и значений локальных переменных.
Затем synthetic HTTP smoke по внешнему адресу проверяет web/API, настоящий pipeline,
JSON и скачивание с checksum клиентом без cookie/API key. Это собственный тестовый
документ, автоматически удаляемый по обычному TTL.

При повторе после `git pull` образ пересобирается, Compose пересоздаёт изменившиеся
собственные компоненты. Shared stack, чужие namespaces и volumes не удаляются.
Изменения `.env` процесса влияют на все команды с тем же приоритетом, что Pydantic.
При изменении настроек очереди уже существующая очередь может отклонить несовместимые
arguments; скрипт не удаляет её и не заменяет молча. Согласуйте миграцию очереди отдельно.

Обновление с сохранением видимых логов:

```bash
git status --short
git pull --ff-only
bash scripts/test.sh
bash scripts/up.sh
bash scripts/test.sh --live
docker compose --env-file .env.example --env-file .env ps
```

Offline tests требуют `uv` и Python 3.12–3.14. `up.sh` не требует uv/Python хоста:
использует собственный образ. `--live` требует поднятый сервис, evaluation key в
собственном Settings и локальные `examples` (пять прежних пар и две новые пары
диапазонов). Если что-то отсутствует, это FAIL,
а не успешный skip. Частные сравнения/замеры сохраняются в игнорируемый `reports/local/`.

Browser prerequisites: доступ к download Playwright и системные библиотеки Chromium.
Скрипт автоматически ставит закреплённый Chromium при флаге browser.
Запуск: `bash scripts/test.sh --browser`, Windows —
`.\ops\check-quality.ps1 -Browser`. Browser-тесты используют настоящие HTTP/Chromium,
но synthetic OCR/VLM; это не подтверждение качества реальной модели.
Если Execution Policy блокирует локальный `.ps1`, используйте разовую команду
`powershell -NoProfile -ExecutionPolicy Bypass -File .\ops\check-quality.ps1 -Browser`.
Она не меняет постоянные политики Windows.

Ручная приёмка из другой разрешённой LAN/VPN-машины:

1. Открыть `http://192.168.55.3:8084/` без экрана входа; `/docs` загружает локальный Swagger.
2. Проверить две вкладки промптов, отдельные тексты, восстановление только активной,
   сохранение сессии и сохранность другой вкладки после обновления страницы.
3. Загрузить `4-2591.pdf`, запустить анализ. Ожидать 1 регистрацию, страницы 1–6,
   четыре приложения и warning о расхождении дат. Подтверждать границы не требуется.
4. Проверить листание, миниатюры, масштаб; обновление SSE не меняет выбранную страницу.
5. JSON до завершения помечен как поток. После проверки — schema_version 1.0,
   экспорт доступен, PDF-комплект содержит 6 страниц, исходник скачивается отдельно.
   Сверить род, номер и дату самого письма с оригиналом: номера/даты договора
   и приложений не должны подменять эти поля. Текущая модель эту приёмку ещё не прошла.
6. Пачка с двумя независимыми письмами даёт две регистрации/PDF. Несколько источников
   сохраняют file_id/page_number в manifest; TIFF сохраняет порядок кадров.
7. Ошибка/отмена показывают диагностический статус и исходники; экспорт неподтверждённого
   JSON недоступен. После TTL ранее выданные ссылки запрещены.
8. Повторить `up.sh`: текущие credentials сохраняются, чужие RabbitMQ users/vhosts не меняются.

Приёмка редактора после обновления:

1. Auto: оба flags по умолчанию; загрузка показывает прогрессивные превью ещё до анализа,
   Start заканчивается JSON без подтверждения.
2. Review: выключить авто, оставить skip выключенным. После предложения VLM увидеть
   `awaiting_confirmation`, выключенный экспорт, кнопку подтверждения. После confirm — PDF/JSON.
3. Skip: включить пропуск границ, auto выключен и disabled. Два отдельных файла дают
   два PDF без segmentation-VLM и без обязательного confirm.
4. Manual-first: сразу после превью разделить диапазон, перетащить границу, повторить
   стрелками/Enter/Escape. Проверить серверный статус сохранения и изменение переключателей.
   Попробовать Merge, Undo, Reset, исключение страницы и Create для её восстановления.
5. В двух вкладках отправить правку одной revision: вторая получает 409 и актуальный план.
   После подтверждения кнопки редактирования заблокированы; refresh сохраняет состав.
6. Исключённая страница остаётся в оригинале/preview, отсутствует в PDF-комплекте.
   Проверить ручные две группы `4-2591.pdf`: ровно два PDF по выбранным страницам.
7. Пакет на 200/1000 страниц: выбирать файл, переходить по сквозному номеру, прокручивать
   ленту. В Network — page API порциями, в DOM — до 24 карточек, viewer сохраняет выбор
   при SSE/polling. Большой pipeline измерять отдельно от скорости UI.
8. На 501 странице листать и прокручивать ленту: нет сообщения rate_limit, выбранный
   лист сохраняется, повторные polling не скачивают одни миниатюры десятки раз.
9. Для перемешанных листов выбрать первый, Ctrl/Cmd-кликнуть связанный несмежный,
   нажать «Создать диапазон»: чужие листы между ними остаются в своих группах.
   Разделить несмежный диапазон, обновить страницу, проверить порядок и сохранение.
10. При page_fallback увидеть предупреждение и черновик по одному листу. До confirm
    экспорт недоступен. Проверить/объединить листы, подтвердить, скачать PDF и оригинал.

Ресурсные параметры в `.env.example`: `UPLOAD_MAX_FILE_MB=400`,
`UPLOAD_MAX_FILE_PAGES=1000`, `DOCUMENT_MAX_MB=400`, `DOCUMENT_MAX_PAGES=1000`,
`UPLOAD_MAX_MB=1024`, `UPLOAD_MAX_PAGES=2000`, `UPLOAD_MAX_FILES=20`.
Файл и комплект ограничены независимо от пачки. Значения MiB, не десятичные MB.
Queue — 1800 с, preview — 3600 с, processing — 14400 с по умолчанию;
waiting — строго 3600 с с preview_ready, terminal retention — строго 3600 с.
`STORAGE_MIN_FREE_MB=1024` оставляет резерв. Реальное место включает оригиналы,
нормализованный PDF, PNG, OCR и комплекты; входные 400 МиБ не равны расходу диска.
Настройки не являются гарантией скорости реальной VLM. Перед обновлением дождаться
завершения старых активных заданий: новый формат Job читается обратно совместимо,
но смешанные worker разных версий одновременно не запускать.

`/health/ready` не доказывает firewall-доступ из другой машины. Firewall ограничивает
только собственный web/API порт разрешённой LAN/VPN; private PostgreSQL не публикуется.
При будущем Internet-доступе отдельно согласуются HTTPS и `COOKIE_SECURE=true`.
Откат: вернуть согласованную версию кода владельцем и повторить `up.sh`, сохранив `.env`
и named volumes. Автоматический destructive downgrade БД не выполняется.
