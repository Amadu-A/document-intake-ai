# Архитектура и решения

FastAPI-монолит имеет собственные API/worker и PostgreSQL в private Docker network.
RabbitMQ, Docling и shared-VLM — внешние зависимости существующей `ai-shared`.
Проект не управляет их lifecycle, GPU или физической моделью.
Слои: domain → application ← infrastructure; presentation/http и web вызывают
общие сценарии. Composition root — `app/core/container.py`.

## Последовательное разделение

С версии `adjacent-ocr-v1` автоматический путь:
загрузка → прогрессивные превью → OCR всех страниц → текстовые сравнения соседей →
непрерывные группы → блокировка состава → PDF → vision-извлечение → JSON 1.0.
В режиме skip сравнений нет; OCR выбранных страниц нужен для извлечения.

Внутри каждого файла из N страниц создаётся N−1 независимых сравнений.
Контекст запроса содержит только `left_page` и `right_page`, в каждой —
`file_id`, `page_number`, `ocr`. Изображения и другие пары не передаются.
Единственный ответ — `{"solution": true}` или `{"solution": false}`.
Строки, числа, null, лишние поля, неполный JSON, повторные ключи отклоняются.
Техническая сборка соединяет только соседей с подтверждённым true.
Между исходными файлами всегда новая группа. Дальние связи автоматически не ищутся.
Заголовки, номера, контрагенты и регулярные выражения не меняют модельное решение.

`application/pairwise.py` обслуживает очередь ограниченным числом корутин,
`PAIR_CONCURRENCY=4`, `PAIR_MAX_ATTEMPTS=3`. Общий семафор одного worker-процесса
ограничивает активные пары его заданий. Для нескольких worker-процессов общий
предел равен сумме их лимитов. Транзакции не удерживаются во время HTTP.
До запроса сохраняются адреса, попытка и running; после — строгий ответ либо код ошибки.
SHA-256 контекста/промпта/версии позволяет переиспользовать завершённые сравнения
после restart. Успешные пары не повторяются. Бюджет попыток переживает restart.
OCR по страницам сохраняется отдельно в private storage; ошибка пары не перезапускает OCR.

Непригодный OCR не запускает скрытый просмотр изображения. Ошибка пары не становится
true/false. После исчерпания повторов или `VLM_SEGMENTATION_TIMEOUT_SECONDS=900`
неразрешённые переходы сохраняются, источник — `vlm_partial`, статус —
`awaiting_confirmation`. Частичные группы — только черновик; финального JSON/PDF
регистраций нет. Редактор показывает проблемные переходы, пользователь изменяет
или явно утверждает состав. Все успешные ответы в auto заканчиваются без confirm.
Review всегда ждёт подтверждения. Ручные несмежные и межфайловые группы разрешены.

Старые оконные модели границ, глобальное/древовидное согласование и автоматический
постраничный запасной путь удалены. Окна с перекрытием остаются только для OCR и
извлечения фактов больших утверждённых комплектов, не для изменения границ.

## Извлечение и экспорт

Vision-извлечение сохраняет изображения, детали шапки/подвала и OCR.
VLM находит приложения только внутри утверждённых страниц. При обнаружении
физических приложений выполняется ограниченная независимая проверка даты основной
части без OCR, затем уточнение фактов. Реквизиты не выводятся из шаблонов OCR backend.
Большие комплекты используют ограниченные окна и согласование фактов;
это не разрешает менять состав регистраций.

Каталог `domain/taxonomy/letters.json` задаёт закрытые пути писем.
Юридический род независим от направления. Без `organization_hint` направление null;
получатель PDF не подставляется как обслуживаемая организация.
Модель возвращает one_c с null; `one_c_projection.py` строит допустимую проекцию
из проверенных фактов и доверенного контекста. Сервис не ищет и не регистрирует в 1С.
Экспорт сохраняет JSON 1.0, физические страницы, отдельные целые PDF, размеры/SHA-256,
подписанные внешние download URLs и исходники. OCR/промпты/локальные пути не экспортируются.
Для ручного межфайлового комплекта JSON привязан к первому источнику;
полная последовательность PageRef находится в manifest, PDF содержит все назначенные листы.

## Состояние, отмена и обновление

Job, события SSE и outbox хранятся атомарно в собственной PostgreSQL.
AMQP допускает повторную доставку; claim, lease и fence исключают повторную публикацию.
Ручная правка отзывает fence и включает skip; confirm фиксирует immutable ApprovedPlan.
Ожидание подтверждения освобождает worker. Queue, preview и processing имеют
раздельные конечные deadlines. Ожидание ограничено часом после готовности состава,
обычные правки не продлевают его. Terminal retention — час после завершения/отмены.

Cancel немедленно фиксирует cancelled и отзывает fence. Worker проверяет активность
каждые 250 мс, отдельно продлевая lease; отменяет выполняемую корутину и дочерние
задачи. Конвертер/PDF работают в отдельных ограниченных процессах, остановка их
прерывает. Отменяется HTTP/ожидание Docling; принятая upstream task может завершиться
в самом Docling, если его API не поддерживает отмену. Общие сервисы не останавливаются.
Поздние ответы не могут опубликовать результат отменённого задания.

«Новый пакет» доступен всегда. После подтверждения отмены сбрасываются DOM/состояние,
input.value, sessionStorage job_id, SSE/polling, запросы чтения, blob URLs и кеши.
Поколение клиента защищает новый экран от старых ответов. При ошибке отмены
предлагаются повтор или явное отсоединение с предупреждением.

Миграция `0002` сохраняет terminal JSON/артефакты, а активные задания прежнего
алгоритма завершает с `algorithm_version_changed`. Их нужно загрузить заново.
Перед миграцией `up.sh` останавливает только собственные API/worker.
Сессионный старый segmentation сбрасывается на v4, extraction override сохраняется.
Новые задания используют неизменяемые snapshots обоих промптов.

## Ограничения адаптеров и безопасность

Docling по умолчанию получает технические окна по 20 страниц (не более 50),
с дополнительным делением по размеру. Async task ID/fingerprint сохраняются закрыто;
restart продолжает polling, успешный OCR проверяется по хешам и настройкам.
Общий semaphore адаптера допускает два окна, включая конкурентные вызовы из разных
документов; возврат к одному задаётся Settings. Короткий POST lock управляет лишь
частотой запросов и общим cooldown; выполнение/polling не удерживают его. Window lock
защищает single-flight до публикации кеша; частичная запись не меняет fingerprint
принятого задания. Отмена дожидается coroutine и начатой записи checkpoint. Результаты
собираются по исходному реестру страниц, прогресс учитывает готовность любого окна.
Polling, retry/backoff и таймауты конечны, 429 не вызывает шторм повторных конвертаций.
Физическое хранилище и повторяемая TTL-очистка не затрагивают активные задания.

Конвертер Linux ограничен CPU/памятью/размером и seccomp без сетевого доступа;
секреты в дочерний процесс не передаются. Office headless отключает macros/внешние связи.
Контейнер nonroot/read-only, capabilities сняты, PostgreSQL не публикуется.
Анонимные HttpOnly/SameSite cookies, CSRF/Origin, отдельные API owners и подписанные
capabilities ограничивают доступ к данным. HTTP-бюджеты команд/чтения/превью раздельны.
UI держит до 24 карточек ленты, 11 миниатюр viewer и 96 изображений в RAM.
Логи содержат только безопасные этапы/коды/время, не документы, OCR, промпты или секреты.
